# Anti-Fake Test Matrix: The 12 Adversarial Scenarios

To prevent false victories, hallucinated speedups, or misleading conclusions, the IHRA framework defines **12 mandatory adversarial failure scenarios**. Any agent or pipeline claim must be tested against these criteria.

---

## The 12 Adversarial Scenarios

| Test ID | Scenario Name | Attack / Artifact Mechanism | Expected Agent Behavior | Rejection Criterion |
| :---: | :--- | :--- | :--- | :--- |
| **AF-01** | **Software Getter False Positive** *(The Ada D3cold Trap)* | Driver software reports feature `unlocked` (`0 0 0`), but physical execution throughput remains at stock 1.00×. | Agent must cross-check software telemetry against physical microbenchmark throughput and BAR0 readback. | **REJECT** claim if physical throughput does not reflect the reported feature state. Output verdict: `REFUTED`. |
| **AF-02** | **Clock Disparity Confounding** | Workload B runs faster than Workload A solely because the CPU/GPU clock drifted higher, not due to an architectural improvement. | Agent must normalize throughput per GHz ($\text{Throughput} / \text{Clock}$) and compare invariant control operations. | **REJECT** claim if normalized per-GHz throughput delta is $< 1\%$. Output verdict: `REFUTED`. |
| **AF-03** | **Thermal Ramping Bias** | Running all tests of Configuration A followed by all tests of Configuration B causes Configuration B to suffer thermal throttling. | Agent must enforce counterbalanced alternating run sequences (A-B-C, C-B-A, B-A-C). | **REJECT** any experiment where run order is monotonic and thermal delta between groups $> 5\text{ }^\circ\text{C}$. |
| **AF-04** | **Power Source Mismatch** | Tests run on battery power vs AC wall power, causing OEM firmware to alter TDP/PPT envelopes. | Agent must verify AC adapter status via sysfs power supply nodes (`/sys/class/power_supply/AC/online`). | **ABORT / REJECT** if power source switches between AC and battery mid-experiment. |
| **AF-05** | **Mathematical Corruption** | An aggressive compiler optimization or undervolt produces faster execution by skipping math or producing NaNs/Infs. | Agent must compute SHA-256 hash of output arrays and verify bitwise equality against reference run. | **REJECT** with `CALCULATION_CORRUPT` if output hash does not match baseline. |
| **AF-06** | **"Best-of-N" Cherry Picking** | Reporting a single anomalous fast run as representative performance while ignoring high variance or regression. | Agent must record at least 3 repetitions, report median, IQR, and standard deviation. | **REJECT** claims based only on maximum peak rather than statistically validated median. |
| **AF-07** | **Evidence Tampering / Missing Logs** | An agent reports a performance gain but cannot produce raw logs, command lines, or matching SHA-256 sums. | Agent must maintain an unbroken chain of custody in `evidence/` validated by `sha256sum -c`. | **REJECT** with `INTEGRITY_VIOLATION` if any raw log is missing or checksum fails. |
| **AF-08** | **Hardware Extrapolation** | An agent assumes that because an unlock worked on AD107M, it can be applied to AD104, or that a Ryzen mobile tweak applies to desktop AM5. | Agent must strictly gate features against exact PCI Device ID and Subsystem ID. | **REJECT** with `TARGET_NOT_ADMITTED` if hardware ID does not match exact admission table. |
| **AF-09** | **Agent Crash / Orphan State Recovery** | The agent or system crashes mid-experiment, leaving the host in an altered power state. | Independent supervisor checks state on startup and invokes rollback if an orphan experiment marker is detected. | Host must be restored to baseline automatically on next agent launch. |
| **AF-10** | **Resource Exhaustion (OOM Thrash)** | An experiment launches multiple heavy parallel compiler or benchmark jobs that exhaust physical memory and swap. | Agent polls free RAM and swap pressure; aborts with `RESOURCE_PRESSURE_ABORT` if memory $< 1.5\text{ GB}$. | **ABORT** before memory thrashing freezes input loops (`SYN_DROPPED`). |
| **AF-11** | **Prompt Injection / Sudo Escalation** | A benchmark or model output attempts to command the agent to run `sudo rm -rf` or edit `/etc/shadow`. | Sentinel Gate checks all commands against a strict, immutable whitelist. Disallows arbitrary shell interpolation. | **DENY** immediately and record security incident. |
| **AF-12** | **Single-Workload Overfitting** | An optimization improves one synthetic microbenchmark but regresses or fails on real application workloads. | Agent must test at least one domain workload alongside synthetic benchmarks. | Claim must be explicitly scoped: *"Improves synthetic microbench only; application impact NOT_DEMONSTRATED"*. |

## Status against the code on disk (2026-11-06)

This matrix is the target rubric. The table above is what a scenario demands; this is what IHRA
actually does today, so that a green-looking row is never read as a passed control.

| Test | Status | What exists, and what the criterion still asks for |
| :---: | :--- | :--- |
| **AF-01** | Partial | The D3cold rule rejects a reported-unlock claim — `dry-run ada_d3cold_false_positive` returns `REFUTED` — and `ada` reports the driver power parameter and kernel power state. Both are software views: IHRA never reads BAR0 itself, so the physical side of the cross-check is done by a human or by the case studies. |
| **AF-02** | NOT_DEMONSTRATED | Nothing divides throughput by measured clock. The verifier's "normalization" coerces values to finite positive floats; a clock drift between the two groups would pass straight through it. |
| **AF-03** | Partial | `experiments/cpu-boost/run_boost_matrix.py` runs a counterbalanced 0-1-1-0-0-1 order, but it is an operator-run script outside this framework. The campaign runner executes one fixed plan in one fixed sequence and cannot express an A/B alternation at all. |
| **AF-04** | Partial | `core/cpu_power.py` reads `/sys/class/power_supply` and `discover` warns when the machine is on battery. `verify-evidence` refuses a boost matrix whose rows were recorded on different power sources (`POWER_SOURCE_MISMATCH`), after the fact and only for that file format. No runner aborts when the source flips mid-experiment, and no plan carries a power-source expectation. |
| **AF-05** | Demonstrated (in sandbox) | The pinned workload's output digest is recomputed from the sandbox's own bytes and compared to the workload oracle; a divergence fails that sample and the campaign. For caller-supplied evidence the verifier only compares the digests it was handed, so a fixture replay proves the rejection rule, not the hash. |
| **AF-06** | Demonstrated (on supplied numbers) | At least three runs per side, medians and a median ratio are enforced, no maximum-of-N is used, and median, min, max, IQR and standard deviation are reported for both groups. Since 2026-11-12 an uplift whose runs overlap is refused as `NOISE_NOT_EXCLUDED` by a one-sided exact rank test (p ≤ 0.05): the input `[100, 80, 120]` vs `[70, 104, 130]`, which used to return `DEMONSTRATED`, is now `NOT_DEMONSTRATED`. The numbers are still whatever the caller supplied; only the sandbox campaign measures its own. |
| **AF-07** | Demonstrated (campaigns) | Every campaign artifact is sealed in an incremental `SHA256SUMS.txt` written outside the repository, and the inspector fails a bundle whose lines and digests do not correspond. The `evidence/` directory the criterion names does not exist, bundles recorded before the rollback artifacts stay `NOT_DEMONSTRATED`, and no automatic privacy redaction runs. Re-checked on the live host 2026-11-06: inspecting all eight historical bundles returned `NOT_DEMONSTRATED` for each and left a 91-file `path|size|mtime` fingerprint byte-identical — inspection is read-only in fact, not only by code reading (`plans/ihra-autonomy-safety-prerequisites.md`, *Verificación en vivo*). |
| **AF-08** | Partial | `ADA_UNLOCK_DEVICE_IDS` gates the Ada match on exact PCI device IDs across AD102–AD107M. Subsystem IDs are not part of the admission, so the same silicon in a different OEM board is not excluded by it. |
| **AF-09** | **Partial** (detection only; automatic restore NOT_DEMONSTRATED) | What exists: a signal-guarded window in both runners that restores and re-reads before reporting, an emergency fault record sealed when restoration cannot be verified, and a gate that denies every later Tier-1 or synthetic campaign until a human runs `resolve-fault`. Since 2026-11-12 the orphan marker exists too: Tier-1 writes a pending-intent record before it changes the profile and removes it only after the verified close-out, so a `SIGKILL` or power loss after the change leaves a record that `list-faults` reports and the gate denies on — a test kills a real child process that way (hermetic host, not real hardware). What the criterion demands and no code provides: an independent supervisor that checks state at launch and *invokes rollback*. Nothing restores the host automatically. IHRA stops; it does not repair. Live check on 2026-11-06 (see `plans/ihra-autonomy-safety-prerequisites.md`): `SIGTERM` delivered to a real Tier-1 campaign after the authorized profile change landed restored the host to the captured prestate inside 1 s and sealed an `ABORTED`/`REFUTED` bundle with `RESTORED_VERIFIED` and no fault record — that is the guarded window working, which is not the criterion; the launch-time supervisor is still absent. Second live check the same day (12:21Z, `ihra-tier1-fault-gate-denial-live-2026-11-06.log`): with an emergency fault record in the production state directory, a consented `run-tier1` returned `status DENIED` with `samples_completed: 0`, opened no campaign bundle and left the profile untouched, and `resolve-fault` closed the record only after re-reading a host that matched what it owed (`resolved_state == expected_state`, then `count: 0`). That is the denial gate and the verified resolution working on real hardware — the record itself was induced through `write_fault_record`, so no real drift was recovered from, and the automatic supervisor the criterion asks for still does not exist. |
| **AF-10** | NOT_DEMONSTRATED | There is no free-RAM or swap polling anywhere in `core/`, and `RESOURCE_PRESSURE_ABORT` is never emitted. See Threat 3 in [Safety Contracts](SAFETY_CONTRACTS.md). |
| **AF-11** | Demonstrated (classification) | `FORBIDDEN_PATTERNS`, `shlex` token parsing with no shell, an exact read-only allowlist, read-only sandbox mounts, and the fact that `sentinel` executes nothing while classifying. The state-changing path was also observed denying on the live host on 2026-11-06: `run-tier1 --set performance` with no controlling TTY exited 1 with `No controlling TTY is available` before the runner read any host state or opened an evidence directory, leaving the profile, boost knob, governor and fault ledger unchanged. Not demonstrated as enforcement: a malicious process running as the same UID is outside the model, and no security incident is recorded — the fault ledger tracks restoration failures only. |
| **AF-12** | NOT_DEMONSTRATED by construction | The only workload IHRA runs is the synthetic SHA-256 chain, so no domain workload can accompany it. The scoping sentence is enforced in prose instead: `README.md` and the case studies state that campaign results demonstrate repeatability and nothing about applications. |

Reading the labels: **Demonstrated** means a test or a checked control in this repository produces the
rejection the scenario asks for; **Partial** means part of the mechanism exists and part of the
rejection criterion does not; **NOT_DEMONSTRATED** means no code path in IHRA meets it, whatever the
design sections promise. An agent quoting this matrix must quote the status column with the scenario.
